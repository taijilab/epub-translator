# EPUB 多语言翻译工具

一个功能强大的客户端 EPUB 文件翻译工具，支持批量翻译、多种翻译质量模式、术语表、智能并发，完全在浏览器中运行，无需后端服务器。

## ✨ 主要功能

- 🌍 **多语言支持** - 支持中文、英语、日语、韩语、法语、西班牙语、德语、俄语、葡萄牙语之间的互译
- 📊 **智能文件分析** - 自动检测文件字数、语言类型
- ⚡ **并发翻译** - API 并发可调（默认 3 路），文本分组减少调用次数
- 🎯 **三种翻译模式** - 快速模式、标准模式、精翻模式，按需选择质量与速度的平衡
- 📖 **术语表支持** - 自定义术语表确保专业术语翻译一致性
- 📈 **实时进度** - 按字数显示翻译进度，实时反馈
- 🔄 **横竖排转换** - 自动检测竖排 EPUB 并转换为横排
- 📖 **保持原文排版** - 完整保留原文的段落结构、HTML 标签和 CSS 样式
- 👁️ **翻译预览** - 翻译完成后可在线预览效果
- 💾 **原文件保护** - 原文件完全不被修改，生成新文件
- 📝 **Token 统计** - 实时显示 token 消耗和预估费用
- 🗂️ **批量处理** - 支持同时上传和翻译多个 EPUB 文件

## 🚀 使用方法

### 全书译名与质量候选检查

- 选择书籍后，在“专有名词手册”中新增概念术语或设置标准译名；全名与简称可以分别指定译文。候选、冲突、已确认支持筛选，列表每页 50 条。
- 已确认译名按文件名和翻译方向保存在当前浏览器。每次任务锁定开译时的版本，运行中修改留给下一次任务生效；可以取消确认。API Key 不包含在这些术语记录中。
- 确认译名变化后，该书后续任务使用隔离缓存；没有确认术语时仍可复用已有缓存。缓存读取按每批最多 256 个键、一次 IndexedDB 事务处理，术语面板更新合并为 80ms 一次。
- 数字差异、疑似残留英文、长度异常、引号、否定表达和多余字符会生成待审校候选。点击报告条目可对照原文与译文，核对后可标记完成或恢复待审校；报告 JSON 包含核对状态。
- 规则检查不是语义正确性的证明，不自动改写译文，也不自动发起付费审校。核对状态尚未跨刷新保存；完整断点续译和独立模型审校仍待实现。
- 回归入口：`http://127.0.0.1:8081/tests/llm.html`。当前 72 项模拟回归通过（含术语导入、编辑、持久化和存储失败回滚），未调用付费 API 测量实际效果。

### 导入与编辑手册

选择 EPUB 后，使用“专有名词手册 → 导入 JSON 手册”。支持本程序导出的 JSON，以及包含 `source`、`target`、可选 `category` 和 `aliases` 的术语数组。导入前可预览，最多5MB、5000条；不同书名可以复用手册，但翻译方向必须一致。

默认导入为候选；勾选“启用文件中已确认译名”才会应用文件中的确认记录。已有确认及其简称不被覆盖，冲突译名保留为候选供核对。重复原译文对跳过，不自动修改已生成的 EPUB。

点击条目旁“编辑”可修改原文、译文、分类、简称和确认状态。导入、编辑的条目和已确认译名保存在当前浏览器，按书籍和语言方向隔离，刷新后重新选择同一本书即可恢复。运行中的已确认术语快照不变，新标准用于下一次任务。Markdown 手册用于阅读，重新导入请使用 JSON。

简单 JSON 示例：

```json
[
  {"category":"人名","source":"Dario Amodei","target":"达里奥·阿莫代伊","aliases":[{"source":"Amodei","target":"阿莫代伊"}]},
  {"category":"技术术语","source":"compute","target":"算力"}
]
```

### 阅读顺序、前文与术语补提取

- 单书与批量任务读取 `META-INF/container.xml` 和 OPF `spine`。主要章节按阅读顺序逐章加载和翻译；`linear="no"` 附属内容及未列入 spine 的导航等文件随后处理。缺失或损坏的 spine 会记录警告并回退文件顺序，不丢弃章节。
- 章内分组仍使用共享 API 并发上限；单书不再把全部章节一起载入和提交。认证或余额错误停止请求，未启动章节以原文写入部分结果。
- 每个翻译请求带最多两个前文片段，只供参考、不返回参考 ID。每个片段的原文和译文各最多 600 字符；章内并发不等待上一组。译文只引用已经通过完整段落恢复校验的结果，任务之间和书籍之间不共享前文。
- 已缓存译文但缺术语元数据时，单独请求只返回 `id + terms`，不要求重复输出全文译文；此类请求使用较小输出预算，DeepSeek Flash 不启用思考。失败保留缓存译文并记录警告，下一次仍可补提取。
- 已有译文缓存继续复用，不会为新增前文自动付费重译。检验新提示词效果需要冷缓存样本；上下文仍是参考，不保证解决所有指代或语义问题。

## 翻译优化

新引擎按完整段落翻译，使用占位符保护强调、链接、脚注等内联标签；长段落按句界分组，不在单词中间截断。同一本书的相同段落共用在途请求，内存未命中时按键查询 IndexedDB。

本书已提取的相关术语会在后续请求发出时注入提示词，首个确认译名优先，用户自定义术语优先于自动术语。已发出的并发请求不会被追溯修改，手册仍保留译名差异。与确认译名冲突的缓存会重新翻译。新缓存按书籍和段落版本隔离，旧文本节点缓存不直接混用。

使用 Kimi、TaoToken、智谱或 OpenRouter 翻译时，同步提取人名、公司名、产品名、地名和技术术语，按书籍独立汇总。手册包含原文、实际译文和出现章节，可按分类、原文或译文筛选，并下载 Markdown 或 JSON。重复词条合并章节，同一原文的不同译名分别保留。

术语与译文一并缓存；旧译文缓存没有术语数据时会补提取，保留原译文。Demo、Google 免费接口和旧自定义翻译接口不提供模型术语提取。

## API 配置

### TaoToken（OpenAI 兼容）

翻译服务选择 TaoToken，输入 TaoToken 控制台的 Key，选择与账号套餐匹配的计费入口，并填写套餐或模型广场中的真实 Model ID。Key 只保留在当前页面，不写入本地存储。测试连接会发送一个简短的模型请求，消耗对应入口的额度。

| 计费方式 | Base URL |
|---|---|
| 按量付费 | `https://api.taotoken.net/v1` |
| Token Plan | `https://api.taotoken.net/token/v1` |
| Coding Plan | `https://api.taotoken.net/coding/v1` |

程序使用 `/chat/completions`，无需填写完整请求路径。响应通过文本片段 ID 校验，再写回 EPUB；缓存与其他平台隔离。

翻译时原文/译文窗口逐组更新；每组最多 32 个片段、3500 字符，减少短段落的请求次数。TaoToken 的 `deepseek-flash` 在快速和标准模式关闭深度思考，在精翻模式启用。实际速度取决于服务端响应和账号限流。

译文采用流式显示，最终完整结果通过 ID 校验后才写入 EPUB。DeepSeek-Flash 费用按 TaoToken 公布的北京时间分时费率累计为人民币估算：工作日 09:00–12:00、14:00–18:00 输入/输出每百万 Token 为 2/8 元，缓存命中 0.04 元；其他时段为 1/4 元，缓存命中 0.02 元（2026-10-14 核实）。优先使用接口返回的 Token 用量；缺失时标记为估算。套餐额度抵扣和最终扣费以平台账单为准。

预览默认打开有正文的页面，以隔离的 `srcdoc` 文档显示，固定窗口高度，避免封面或 iframe 高度问题导致看不到正文。

[TaoToken 官方接口文档](https://taotoken.net/doc/文本对话/OpenAI兼容)。

### Kimi 开放平台

1. 在 Kimi 开放平台创建 API Key，并确认 API 余额；Kimi Pro 会员额度与开放平台 API 分开。
2. 翻译服务选择 Kimi，输入 API Key。密钥只留在当前页面，刷新后需重新输入。
3. 国内 Base URL 默认 `https://api.moonshot.cn/v1`；国际平台可用 `https://api.moonshot.ai/v1`，密钥必须与平台匹配。
4. 点击「测试连接」获取当前账号的模型列表，再选择模型。默认填入 `kimi-k2.6`。
5. API 并发默认 3，可设为 1–10；遇到限流建议降低并发。Google 免费接口仍使用独立的 3 路上限。

Kimi、智谱和 OpenRouter 使用统一的 JSON 文本片段 ID 校验流程。每个片段保留原始文本节点位置，响应顺序不影响写回。ID 缺失、重复、译文为空或输出截断时会重试，失败则保留原文并列入失败报告。报告含文件名、章节、片段 ID、原文和错误，可导出 JSON。

缓存按服务、端点、模型、质量模式、术语表、提示词版本和语言隔离，旧缓存不会混用。翻译开始后固定任务配置，并发数可在运行时调整。重新翻译时会复用成功片段的缓存。

离线模拟回归测试：启动本地服务后访问 `/tests/llm.html`，无需 API Key，不会请求外部翻译服务。

接口参考：[Kimi 官方文档](https://platform.kimi.ai/docs/guide/kimi-k2-6-quickstart)。

## 🎯 翻译质量模式

### 快速模式
直接翻译，速度最快，适合快速浏览内容。

### 标准模式（默认）
先分析原文风格和术语，再进行翻译。兼顾质量和速度。

### 精翻模式
完整翻译工作流：分析 → 初译 → 审校 → 润色。适合出版级质量要求。

核心翻译理念借鉴 [baoyu-translate](https://github.com/JimLiu/baoyu-skills) 技能：**重写而非逐字翻译**，产出如同目标语言母语作者撰写的自然流畅文本。

## ⚡ 性能优化

### 当前共享 LLM 流程（validated-v4）

- 自动提取译名仅作候选参考；按词边界匹配，译名差异保留译文并列入待审校报告，不触发付费重译。
- 可解析响应按 ID 分别验证，只重试异常项；无效 JSON 或截断响应才拆组修复。修复请求附带具体错误。
- 401、402、403 停止整个任务并排空等待队列；保留已验证结果供下载。连接测试可单独再次执行。
- 默认每片段最多额外重试 2 次；每书额外请求最多 32 次，预估重试 Token 预算 128,000，可在界面调整，设为 0 禁用相应重试。
- Token 预算按请求输入估算加完整输出限额预留，属于保守的重试额度控制，不是账单级费用硬上限，也不限制首次正常翻译请求。
- 完整段落恢复标签成功后才提交缓存、术语和成功字数；部分失败、待审校和任务停止分别显示。
- 模拟回归入口：`http://127.0.0.1:8081/tests/llm.html`。测试替换了 fetch，不消耗真实 API 额度。
- 空页码锚点（如 `span#page_20`、EPUB `pagebreak`）由程序保留和恢复，不交给模型携带占位符；强调、链接、脚注仍严格保护。锚点在译文段落中按相对位置近似恢复，不代表原版固定分页完全对应。
- 已验证的 v4 单段缓存支持移除旧页码占位符后复用；无法安全对应的多片段缓存不做迁移。未完成片段需要重新翻译，既有译本不会自动被修改。

下表描述旧流程参数，不适用于上述共享 LLM 引擎。

| 参数 | 值 | 说明 |
|------|------|------|
| API 并发请求 | 默认 3，可调 1–10 | Kimi、智谱、OpenRouter 共用请求队列 |
| HTML 文件并行 | 8 | 同时处理多个章节文件 |
| 段落分组 | 500-800 字/组 | 减少 API 调用次数 |
| 每组最大段落数 | 12 | 平衡分组大小 |
| 重试策略 | 指数退避 500→1000→2000ms | 自动处理限流 |
| 未翻译重试 | 并行（10 路并发） | 快速补翻遗漏段落 |
| 翻译缓存 | FNV-1a 哈希，1000 条 | 避免重复翻译 |
| 批次间延迟 | 0ms | 无额外等待 |

### 深度思考设置

TaoToken DeepSeek Flash 系列的深度思考默认关闭，可独立勾选开启，不再由精翻模式自动开启。精翻仍使用原有翻译和自我审校提示词。设置保存在当前浏览器，并在开始任务时锁定；运行中修改于下次任务生效。仅补提取缓存术语的请求始终关闭思考。

### 截断与修复调度

TaoToken DeepSeek Flash 翻译每组最多 16 个片段、2000 字符；开启思考时按 1200 字符分组（完整的单片段可超过该软限制）。输出预算随文本长度和片段数调整，最高 8000 tokens。拆分和定向修复优先于尚未开始的普通组，仍遵守共享并发上限。重试预算保留保守预留机制，耗尽时显示具体上限且不发送请求。

### 审校降噪与标签修复

数字比较先统一全半角；原文已有的拉丁字母词不再作为新增外语残留提示，纯外语引文原样保留不再触发英文未翻译提示。新出现的外语词和真正数字差异仍提示。标签定向修复附带每项必须保留的占位符清单；术语提取排除普通名词、代词、自称和敬称。已有译文不会自动改写。
